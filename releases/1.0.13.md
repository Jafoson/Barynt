# Barynt 1.0.13

**Barynt now has documentation for everything.** A complete guide for the people who use and run it, a full API reference and developer docs, in English and German, one click away from the app.

## ✨ Highlights

- **A user guide for everyone, not just developers** — what Barynt is, how issues, boards, views and dashboards work, who may do what, and how to set up sign-in, email and storage. 34 pages with screenshots, in English and German.
- **Docs one click away** — a new book icon at the bottom of the sidebar, next to the version, opens the documentation in your language.
- **Every API route, in one place** — all REST endpoints with parameters and examples, the filter language, the webhook events and all 37 MCP tools.
- **Developer docs** — setup, architecture, data model, permissions, testing and releasing, for everyone who wants to change Barynt.
- **Searchable** — press `/` or `⌘K` on the docs site to find anything.

## 📚 The documentation

Everything lives at **[barynt.dev/docs](https://barynt.dev/docs/)**, and in the repository as plain Markdown, so it always matches the version you run.

- **Getting started.** What Barynt is, the building blocks (workspaces, projects, issues), your first steps and a tour of the settings.
- **Using Barynt.** Issues in detail, writing and formatting, sub-issues and relations, projects, board and list, views, dashboards, your inbox, shortcuts and sharing an issue.
- **Administration.** Workspace settings, members and invitations, teams, roles and permissions, project settings, sign-in and SSO, email, storage, the audit log, platform administration and troubleshooting.
- **Integrations.** The REST API with keys and scopes, webhooks with signature checks, and the MCP server for AI assistants.
- **Reference.** Every endpoint, filter and event, generated from the same data the app uses, so it cannot fall behind.
- **For developers.** How Barynt is built and how to contribute.

## 🔗 A link in the app

Under your name in the sidebar you now find the version, the release notes and a **book icon**. It opens the documentation in English or German, matching the language of the app.

## 🚀 Install in one command

On a Linux server with Docker and a domain pointing at it:

```bash
curl -fsSL https://github.com/barynt-dev/barynt-web/releases/latest/download/install.sh | sh
```

The installer asks a few questions, sets up Barynt with HTTPS (Caddy, automatic Let's Encrypt) and waits until it is healthy. For automation, answer up front: `sh -s -- --domain issues.example.com --yes`. Prefer to read it first? Download `install.sh`, look at it, then run `sh install.sh`.

Afterwards the same script is your **`barynt` command**: `barynt status`, `upgrade`, `backup`, `restore`, `logs`, `config`, `doctor` and `uninstall`. Upgrading is one command, and migrations run on their own.

The release carries `install.sh`, `docker-compose.yml`, `Caddyfile`, `example.env`, their `SHA256SUMS` and a keyless cosign signature of the installer (`install.sh.sigstore.json`).

## ☸️ Kubernetes

The signed Helm chart comes with production building blocks: a PodDisruptionBudget, scheduling controls, an ingress for files, network policies and backups.

```bash
helm install barynt oci://ghcr.io/barynt-dev/charts/barynt
```

## 🩺 Health endpoints

`/api/health` says whether the app can serve requests (its database answers), `/api/health/live` only whether the process is up. The installer, the compose file and the chart use them.

## 🔏 Signed releases

The Docker image (amd64 and arm64), the Helm chart and the installer are signed, and the image is scanned before it is published. One release run now publishes all of it.

## 🏠 A new home

Barynt now lives in the **barynt-dev** organization on GitHub: [github.com/barynt-dev/barynt-web](https://github.com/barynt-dev/barynt-web). Old links keep redirecting.

From this release on, the Docker image and the Helm chart are published under the new name:

- Image: `ghcr.io/barynt-dev/barynt` (was `ghcr.io/jafoson/barynt`)
- Chart: `oci://ghcr.io/barynt-dev/charts/barynt` (was `oci://ghcr.io/jafoson/charts/barynt`)

`barynt upgrade` takes care of it: it downloads the new `docker-compose.yml` of the release, which already points at the new image. If you run your own Compose file or Helm values, change the image path once. Earlier versions stay where they are and keep working, they just do not get new releases.
